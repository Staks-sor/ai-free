# SYNVOX project context

Updated 2026-11-25, Codex. SYNVOX0.5.65 ends new sales and distributes Desktop/VS Code/JetBrains free for personal use under the existing license. Prior payment reconciliation and support remain available. Start with `docs/development/INDEX.md` and the relevant direction.

## Purpose and architecture

SYNVOX is a local chat and coding client using provider-owned web sessions, with desktop, VS Code and JetBrains interfaces. `src/window-app/server.mjs` handles UI/API/dispatch; `src/providers/` owns transport/auth/account isolation; `src/code-agent/` runs permission-checked workspace tools; `src/harness/` persists tasks/checkpoints/plans/verification; `src/state/window-state-store.mjs` manages revisions. `src/agent-orchestrator/` assembles instructions, memory and skills. `plugin-for-vscode/src/` mirrors shared source via `scripts/sync-plugin-runtime.mjs`; JetBrains bundles that runtime. Core model catalog and translations live in `packages/core/`.

## Accepted behavior

Discussion mode prevents automatic workspace execution; Execute mode uses the agent loop. Project claims require tool evidence. Project/Computer access persists per chat. Saved tasks retain provider/workspace/account/session/role and checkpoint; restart marks abandoned tasks interrupted without resending. Unknown delivery, interrupted tools and cancelled turns require evidence before replay. Read-only recovery verifies the exact provider branch/prompt/model. Manual handoff creates another same-workspace chat without transferring provider sessions or automatically sending. `verify_task` runs permitted checks; mutations and executed commands invalidate previous success. Semantic acceptance and arbitrary-shell changed-file inference remain incomplete. Details: `HARNESS.md`, `COMPUTER_ACCESS.md`, `REQUEST_POLICY.md`.

Five web providers support ten accounts each, isolated auth/profiles/fingerprints and chat affinity. Identity checks, CAS/activity leases and account-owned sessions prevent accidental account switching. Existing chats keep their account. Account switches after limits do not bypass provider restrictions. Browser resource budgets and separate login/profile ownership remain. Storage uses coalesced revision-aware writes, awaited checkpoints/finals and corruption preservation; SQLite replacement and cross-device sync are not planned in this task. `PROVIDERS.md`, `STORAGE_PLAN.md`.
