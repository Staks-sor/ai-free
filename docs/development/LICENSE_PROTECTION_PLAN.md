# План защиты подписки и перехода к приложению

2026-10-14, Codex, `main/3db7d9c`. Предложение; реализация и публикация не выполнялись. База: `LICENSE_AUDIT-2026-10-14.md`; `docs/SUBSCRIPTION_PRD.md` — исторический Draft.

## Цель и предел защиты

Закрыть обход запуском, повторные trial и совместное использование; выпускать установщики для трёх ОС. Сохранить чаты, проекты, provider-сессии локально.

Владелец компьютера может модифицировать программу. Подпись entitlement мешает подделывать claims, но пользователь может удалить verifier. Шифрование или загрузка кода после оплаты не дают абсолютной защиты. Выпущенные копии невозможно надёжно отозвать, если они перестают обращаться к серверу.

## Архитектурные варианты

| Вариант | Результат | Ограничение |
|---|---|---|
| Установщик + обязательная локальная проверка + серверные аккаунты | Усложняет простой обход, закрывает выдачу trial новым installation-key | Изменённые клиенты всё ещё могут исполнять локальные функции |
| Сервер выполняет реальную платную операцию | Удаление локальной проверки не воспроизводит результат операции | Нужны сеть, ресурсы, политика данных; операция должна отсутствовать в клиенте |

Предложение: начать первым вариантом. Для второго выбирать полезную функцию: облачный запуск/координацию компьютеров, синхронизацию или резервное копирование. Такие функции защищают собственный сервис; локальный чат остаётся воспроизводимым. Перенос основного Harness на сервер изменит приватность/работу без сети и требует отдельного решения. Endpoint, возвращающий только `allowed`, не создаёт такую зависимость.

## Этапы и приёмка

1. **Закрыть запуск.** `licensing/client.mjs`, CLI/API/agent gates, сборка и зеркала IDE. Production key/endpoint закреплены; коммерческая проверка обязательна. Проверить отсутствие доступа без proof через каждый entry, expiry/revocation и сохранение чтения/экспорта/оплаты. Тестовый режим отделён. Риск: блокировка существующих пользователей; сохранить signed-cache и понятное восстановление.
2. **Аккаунт и устройства.** `services/licensing`, клиентская активация, UI. Выбрать подтверждённую identity Telegram/email. Trial3дня однократно на аккаунт, история выдачи и registration limits; смена installation-key не обновляет trial. Сохранить текущие оплаченные периоды/договорный лимит установок. Проверить миграцию копии БД, replay/concurrency/idempotency, отзыв устройства. Backup/rollback до production; новые аккаунты всё ещё могут злоупотреблять trial.
3. **Desktop установщики.** Исследовать Electron как оболочку существующего Node/HTML продукта; сначала проверить SQLite, RobotJS, browsers, ресурсы и остановку процессов. Windows installer, macOS app/DMG, Linux package; Node/npm пользователю не требуются. Подписанные обновления; integrity/fuses и системная подпись где поддерживаются. Проверить чистые машины, подменённый пакет, restart/data preservation. IDE получают общий guard; упаковка Desktop не защищает отдельные плагины.
4. **Измерение результата.** Серверные агрегаты trial/expired/paid/license-checks/version с минимальными данными и прозрачной политикой. Не отправлять prompts/files/cookies. До/после: частота новых trial, доля оплат, ошибки активации; не объявлять client events доказательством выполнения.
