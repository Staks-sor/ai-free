# Хранилище: план и приёмка

2026-10-13, Codex, `main/3db7d9c`; незакоммичено. Защита состояния Desktop/VS Code.

1. **Воспроизведение.** Два независимых процесса читают одно состояние и сохраняют разные чаты. Обе правки должны остаться. Конкурентные изменения одного чата должны дать явный конфликт без перезаписи.
2. **Запись.** Сохранять полную подготовленную версию через временный файл, fsync и атомарное создание номера версии. При занятом номере перечитать состояние и объединить изменения относительно локальной исходной копии. Хранить текущую и предыдущую исправную версии; старый state.json — источник миграции.
3. **Семантика.** Сохранять внешние новые чаты и удаления; конфликтующие правки чата/pipeline не терять. Подключить очередь окна и синхронный API миграции. Ошибка checkpoint блокирует дальнейшее действие.
4. **Задачи.** Второй backend не должен помечать работу живого первого процесса прерванной или запускать её повторно.
5. **Приёмка.** Реальные дочерние процессы, перезапуск, повреждённая последняя версия, прерванная запись, удаление, миграция, full coverage/build/CI и сравнение зеркал.

Синхронизация открытых окон подключена к существующему `/api/state` опросу. Linux GUI и CPU/RAM всей программы остаются следующими этапами. Развёртывание и удаление пользовательских данных сюда не входят.
