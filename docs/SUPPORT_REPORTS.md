# Отчёты поддержки SYNVOX

2026-11-10, Codex. Исходники незакоммичены. Клиент0.5.64 выпущен с локальным сохранением отчётов; серверный приём не опубликован и выключен.

## Что работает в исходниках

В чате рядом с сообщением об ошибке и в Настройки → Статус доступна кнопка сообщения о проблеме. Форма принимает описание, необязательный контакт и одно изображение. Подготовка выполняется локально. Перед отправкой доступны сводка, полный JSON, изображение и отдельное непредустановленное согласие только на это обращение. Изменение полей аннулирует прежний подготовленный отчёт. Без сети или при отключённом приёме отчёт сохраняется в файл.

Техническая часть строится по списку разрешённых полей: фактическая версия backend, хеш исполняемых исходников, тип клиента, версия IDE/плагина при наличии, ОС/архитектура, Python/Camoufox, провайдер/модель, коды ошибок и до60 структурированных событий. Чаты, код проектов, Git, пути, hostname, лицензионные/аккаунтные идентификаторы, cookies и токены автоматически не включаются. Это не заявление об анонимности всех возможных обращений: человек может добавить персональные данные в текст или изображение. Известные форматы секретов в тексте маскируются, но предварительный просмотр обязателен.

PNG/JPEG/WebP преобразуется браузером в PNG до1280px; сервер проверяет размеры и повторно кодирует только пиксели, исключая метаданные. Максимум изображения1.5MB после нормализации, HTTP-тела3MB. Форма ограничивает входной файл10MB. Отдельный клиентский UUID относится к обращению, не к установке/лицензии. Технические события Qwen сохраняют категории ресурса, HTTP-статус, тип сетевого отказа и флаги готовности без URL/query/headers. Для DeepSeek фиксируются статус/исход CAPTCHA и только известные коды ошибок сервиса. Python определяется из PATH; поле Camoufox указывает требуемую версию пакета из исходников и не доказывает запуск браузера или успешный запрос.

Локальные маршруты `/api/support/{drafts,send,discard}` защищены существующей loopback/session/origin проверкой и доступны независимо от оплаты. До согласия нет отправки отчёта во внешнюю сеть. Сервер отправляет ровно сохранённую копию просмотренного отчёта. При неоднозначном сетевом результате повторяется тот же UUID; приём идемпотентен. Чужое содержимое с тем же UUID отвергается.

## Приём и Telegram

Отдельный `services/support/` не использует БД лицензий. HTTP4330 слушает только127.0.0.1; внешние POST с Origin запрещены. Запросы ограничены по размеру и частоте; хеш адреса используется только временно в памяти для ограничения нагрузки. Полные обращения и доказательство согласия хранятся в закрытой папке0700, файлы0600; подтверждение возвращается после записи/fsync. Не включайте access logs с IP/телами запросов.

Панель `/support-admin/` защищена отдельным длинным паролем Basic Auth через HTTPS, не допускает индексацию или внешние скрипты. Кодирование вывода предотвращает выполнение HTML из обращения. Токен бота и цифровой chat_id владельца остаются на сервере. В Telegram отправляется только общее уведомление и постоянная ссылка на панель — без номера, контакта, текста, ОС, версии или изображения клиента. Ошибка Telegram оставляет уведомление в очереди и не отменяет квитанцию приёма; возможны повторные общие уведомления при сбое между доставкой и сохранением результата.

Срок хранения30дней. Очистка запускается при приёме/просмотре и раз в минуту в сервисе, включая отключённый приём. Для досрочного удаления после проверенного обращения владельца:

```sh
node services/support/delete.mjs /var/lib/synvox-support UUID_ОБРАЩЕНИЯ --confirm
```

Не делайте неограниченных копий каталога: сроки и удаление должны распространяться на все резервные копии. При полностью остановленном сервисе автоматической очистки нет; оператор должен удалить истёкшие данные до возобновления и учитывать период простоя в эксплуатации.

## Что требуется до включения

Владелец подтвердил, что текущий сервер сайта находится за пределами РФ. **Приём и клиентская отправка по умолчанию выключены. На действующий сервер сервис не публиковался; Telegram владельца не тестировался реальным сообщением.**

1. Выделить и подтвердить сервер/хранилище в России. `support.synvox.pro` должен указывать непосредственно на него; не пропускать сбор через зарубежный сервер сайта. Текущая конфигурация региона не проверяет географию автоматически.
2. Проверить основание обработки, отдельный текст согласия/политику, сведения об операторе, уведомление РКН и необходимые меры защиты. Подготовленный текст — проект для проверки, не юридическое заключение и не подтверждение соблюдения закона. Один код ошибки сам по себе не определяет человека, но контакт, изображение, свободный текст или связь номера с человеком могут быть персональными данными. Нажатие «Отправить» не отменяет требований локализации.
3. Собрать отдельный runtime: в корень staging положить `services/support/package.json` как `package.json`, `src/support/report.mjs`, каталог `services/support/`, `services/licensing/telegram-transport.mjs`; положить рядом `services/support/package-lock.json` как `package-lock.json`, затем выполнить `npm ci --omit=dev --ignore-scripts`. Установить Node22+, отдельного пользователя сервиса и приватные каталоги. Примеры unit, Caddy и env рядом с сервисом. Секреты вне репозитория, права0600. Платёжный сервис не менять.
4. Получить подтверждённый цифровой ID личного чата @Staks_sor с ботом; одного username недостаточно для private Bot API. Не выбирать ID из клиентских платежей/чужих чатов. Настроить пароль панели и bot token только в защищённых файлах. Проверить доступ владельца через HTTPS и тестовое общее уведомление с его разрешения.
5. Только после этого включить серверные `SYNVOX_SUPPORT_STORAGE_REGION=RU`, `SYNVOX_SUPPORT_OPERATOR_READY=1`. После HTTPS-приёмки включить `SYNVOX_SUPPORT_REPORTING_ENABLED=1` в следующем клиентском релизе. Не повышать флаг на текущем зарубежном хосте. До включения доступно локальное сохранение файла.
