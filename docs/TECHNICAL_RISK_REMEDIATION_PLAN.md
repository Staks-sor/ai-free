# План устранения технических рисков

## Цель

Снизить риск расхождения desktop-версии и расширения VS Code, стабилизировать тесты и выпуск версий, а затем безопасно разделить крупные модули без одновременной переработки всего проекта.

## Проверенное текущее состояние

- Полный `npm test` проходит успешно.
- Недетерминированность теста поисковика была вызвана влиянием системного `LANG`: тест ожидал DuckDuckGo, но не передавал locale явно. Тест теперь передаёт `{ locale: "en" }`.
- Desktop, расширение VS Code и плагин PyCharm синхронизированы на версии `0.4.24`.
- `.gitignore` уже содержит `.DS_Store` и `*.vsix`.
- Находящиеся локально `.vsix` и `.DS_Store` не отслеживаются Git. Удаление их из истории сейчас не требуется; при необходимости очистка старой истории должна выполняться отдельной согласованной операцией.

## Принципы выполнения

1. Один этап — один отдельный коммит или pull request.
2. Перед каждым этапом фиксировать исходный `git status` и запускать полный `npm test`.
3. Не переносить одновременно UI, сервер и API.
4. Сначала добавлять архитектурные проверки, затем менять структуру.
5. После каждого переноса сохранять обратную совместимость импортов либо менять все импорты в одном атомарном коммите.

## Метрики результата

- Полный тестовый набор стабильно зелёный.
- Количество дублирующихся идентичных модулей уменьшается после каждого PR.
- Shared-модули имеют одну реализацию и используются обоими продуктами.
- Ни один основной entry-point не растёт после начала декомпозиции.
- VSIX и системные файлы не отслеживаются Git.
- Версия каждого продукта определяется из его `package.json`, а правила релиза задокументированы.
